# T04 과제 제출 보고서 원고 v3

내용 구성은 `card-news-maker/docs/과제_제출_보고서.pdf`와 `odd-one-out/과제_제출_보고서.pdf`의 카드별 설명→증거→기술 결정→트러블슈팅→검증 안내→체크리스트 흐름을 참고했다. 본문 근거는 현재 프로젝트의 기획, 과제 요구사항, AI 3줄, 검증 체크리스트, 트러블슈팅, 검증 안내서, 작업내역 체크리스트다.

## 1. 표지

오늘의 진짜 정보판 — 데이터가 안 올 때. Upbit BTC/KRW 일봉과 데이터 실패 상태를 정직하게 보여주는 공개 정보판.

## 2. OVERVIEW · 프로젝트 개요

현재값만 보여주는 화면은 출처·시각·실패 여부를 설명하지 못한다. 이 프로젝트는 값·단위·출처·두 시각·KST, 장애 상태, 일별 기록과 어제 대비 계산을 한 화면에 결합한다.

## 3. USER GUIDE · 30초 확인 방법

1. 메인 화면의 값·단위·출처·두 시각·KST를 확인한다.
2. 실제 날짜 2행과 변화값을 확인하고 출처 링크를 한 번 누른다.
3. `/verification`에서 장애 5종, 빈 상태, 복구를 확인한다.

## 4. CARD 1 · 매일 궁금한 값 하나

Upbit 공개 BTC/KRW 일봉을 사용한다. 실제 조회 화면에 값, KRW, Upbit 출처, 원천 관측 시각, 조회 시각, Asia/Seoul를 표시한다.

## 5. CARD 1 · 화면 증거

현재값·단위·출처·원천 시각·조회 시각을 한 화면에서 확인한다.

## 6. CARD 2 · 비밀 없는 호출

브라우저는 `/api/widgets/*`만 호출하고 서버가 외부 공급자를 조회한다. 소스·배포 파일·네트워크·Git의 비밀값 검색 결과는 0건이다.

## 7. CARD 2 · 출처 링크 증거

출처 링크를 한 번 누르면 Upbit 원자료 페이지가 새 탭에서 열린다.

## 8. CARD 3 · 다섯 가지 실패

timeout, 401/403, 429, offline, schema 변경을 합성 시험값으로 재현한다. 오류 종류·화면 문구·마지막 정상값·다시 시도를 각각 구분한다.

## 9. CARD 3 · timeout 증거

느린 응답을 별도 시간 초과 상태로 표시한다.

## 10. CARD 3 · 인증 실패 증거

외부 원천의 401/403 거절을 인증 실패로 표시한다.

## 11. CARD 3 · 호출 제한 증거

HTTP 429를 호출 제한으로 표시한다.

## 12. CARD 3 · 오프라인 증거

네트워크 연결 실패를 별도 오프라인 상태로 표시한다.

## 13. CARD 3 · 응답 형식 변경 증거

필수 필드가 없는 JSON을 정상 데이터로 사용하지 않는다.

## 14. CARD 3 · 마지막 정상값과 빈 상태

마지막 정상값이 있으면 오래된 데이터로 보존한다. 정상값이 없으면 값을 만들지 않고 빈 상태를 표시한다.

## 15. CARD 3 · 다시 시도 복구

다시 시도 뒤 fresh 상태와 정상 데이터로 돌아온다. 공개 recover-d2 asset 검증은 파일 부재로 보류한다.

## 16. CARD 4 · 하루 한 줄

`날짜 + 데이터 종류`를 고유키로 사용하고 Asia/Seoul 기준 같은 날짜의 성공 응답을 한 행으로 병합한다.

## 17. CARD 4 · 중복 방지 증거

같은 날짜를 반복 동기화해도 고유 행 수가 늘지 않는다.

## 18. CARD 5 · 실제 이틀과 어제 대비

2026-08-25 109,165,000 KRW와 2026-08-26 109,830,000 KRW의 원천·저장·계산 입력·화면값을 대조한다.

## 19. CARD 5 · 변화 계산 증거

차이는 `+665,000 KRW`, 변화율은 `+0.61%`이며 손계산과 화면이 일치한다. 원천과 저장값이 다르면 계산을 중단한다.

## 20. TECH DECISION · 왜 서버 Route Handler인가

키 필요 공급자를 브라우저에서 직접 호출하면 비밀값이 노출된다. 서버 Route Handler와 provider adapter를 경계로 두고 응답 검증, 오류 분류, TTL cache, dedupe, stale fallback을 공통 처리한다.

## 21. ARCHITECTURE · 시스템과 위젯

Next.js, React, TypeScript strict, TanStack Query, Vitest, Playwright, Vercel. 위젯은 Lost Ark 공지·거래장, Upbit, 수출입은행 환율, GitHub Status 5개다.

## 22. TROUBLESHOOTING 1 · SSR과 브라우저

PowerShell npm.ps1 차단은 npm.cmd로 해결했다. prerender document 접근은 서버 경계 검사로 막았다. 상대시각 hydration 불일치는 고정 server snapshot과 client clock 구독으로 해결했다.

## 23. TROUBLESHOOTING 2 · 공급자와 배포

수출입은행은 종료된 도메인에서 신규 oapi로 이전했다. Lost Ark는 유효 CategoryCode 순회와 실제 조회 가능한 기본 아이템으로 수정했다. Vercel 전환 중 일시 404의 실패·성공 증거를 모두 보존했다.

## 24. TROUBLESHOOTING 3 · 증거 덮어쓰기

최초 파일명 충돌 뒤 실행 UTC 시각을 폴더명으로 사용하고 기존 폴더가 있으면 중단하도록 바꿨다. 최초 덮어쓴 픽셀은 복구 불가라는 사실도 숨기지 않았다.

## 25. AI 3줄

- AI에게 맡긴 일: 기존 코드 보존, 장애 5종, 일별 기록, 비교, 자동 테스트, 증거 문서
- 직접 판단한 일: 복사본에서만 작업하고 실제 Upbit 일봉을 사용
- AI 말을 안 들은 일: 기존 증거 덮어쓰기와 미완료 항목의 허위 통과

## 26. VERIFICATION GUIDE 1 · 어디로 가나요 / 무엇을 하나요

공개 주소와 `/verification`으로 이동한다. 메인→출처/기록→장애 검증의 3단계로 확인한다.

## 27. VERIFICATION GUIDE 2 · 통과 기준 / 안 될 때

값의 맥락, KST 두 날짜, 비교값, 서로 다른 장애 문구, stale/empty가 보이면 통과다. 값은 Upbit 필드, 날짜는 localStorage 고유키, 장애는 오류 종류와 다시 시도를 대조한다.

## 28. CHECKLIST · C01~C16

## 29. CHECKLIST · C17~C28
