## 페이지 4 — 데이터 호출 구조

브라우저 → Next.js Route Handler → provider adapter → Upbit 공개 API → 응답 스키마 검증 → 화면·일별 기록.

외부 API를 브라우저가 직접 호출하지 않으며 비밀값은 서버 경계 밖으로 보내지 않는다.

## 페이지 24 — 검증 안내

1. 공개 주소의 값·단위·출처·시각·KST를 확인한다.
2. 일별 두 행과 변화값을 확인하고 출처 링크를 한 번 누른다.
3. `/verification`에서 장애 5종·빈 상태·다시 시도 복구를 확인한다.

통과 모습은 현재/오래된/빈 상태가 구분되고, 실패마다 문구가 다르며, 원천·저장·화면값과 계산이 일치하는 것이다.

## 페이지 25 — 최종 상태와 AI 판단

### 완료

공개 무로그인 주소, 데이터 맥락, 비밀값 0건, 장애 5종, stale/empty/retry, 중복 방지, 실제 원천 2건 대조, 문서와 증거.

### 보류

실제 다음 KST 날짜의 앱 재실행과 제공되지 않은 공개 asset 패키지 SHA-256.

### AI와 본인 판단

- AI에게 맡긴 일: 오류 분기·일별 기록·자동 검증·증거 문서화
- 직접 판단한 일: 공개 원천 선택, KST·단위·계산 규칙 대조
- 따르지 않은 제안: 합성 값을 실제 날짜 기록처럼 저장하지 않음

## 페이지 26 — 기획 배경과 사용자

`README.md`, `계획.md`, `docs/01_기획.md`의 핵심 내용.

- 대상: 매일 BTC/KRW 움직임을 빠르게 확인하려는 사용자

- 해결: 데이터 맥락과 실패 상태, 일별 변화, 검증 근거를 한 화면에 결합한다.
- 구현 전략: 기존 대시보드 구조를 보존하고 T04 요구 기능만 확장한다.

## 페이지 29 — 트러블슈팅 기록

`docs/트러블슈팅.md`와 감사 기록의 핵심 내용.

- 401과 429가 같은 오류로 보이던 문제 → HTTP 상태별 오류 종류 추가
- 오프라인과 timeout 혼동 → 네트워크 상태와 Abort 오류 분리
- schema 변경 시 전체 화면 중단 → 경계 검증 후 empty/stale fallback
- refresh cooldown이 장애 주입을 삼키던 문제 → 장애별 독립 browser context 사용
- 원천 네트워크 timeout → 실제 기록을 조작하지 않고 보류 기록
