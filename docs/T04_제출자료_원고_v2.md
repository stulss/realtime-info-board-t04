# T04 제출자료 원고 v2

이 원고는 다음 7개 문서만 본문 근거로 사용한다: `docs/01_기획.md`, `docs/00_과제_요구사항_매핑.md`, `docs/AI_3줄.md`, `docs/T04_검증_체크리스트.md`, `docs/트러블슈팅.md`, `docs/검증안내서.md`, `작업내역_체크리스트.md`. 검증 주장은 기존 스크린샷을 바로 뒤 증거로 연결한다.

## 페이지 1 — 표지

오늘의 진짜 정보판 — 데이터가 안 올 때. 실제 데이터의 값·맥락·실패 상태·일별 변화를 정직하게 보여주는 공개 대시보드.

- 공개 주소: <https://realtime-info-board-t04.vercel.app/>
- 소스: <https://github.com/stulss/realtime-info-board-t04>

## 페이지 2 — 사용한 문서와 증거 원칙

기획, C01~C28 매핑, AI 3줄, 검증 체크리스트, 트러블슈팅, 검증 안내서, 작업내역 체크리스트를 사용했다. 모든 검증 결과에는 관련 스크린샷을 연결하고 합성 장애 데이터와 실제 날짜 기록을 구분한다.

## 페이지 3 — 기획: 프로젝트 개요

실시간으로 변하는 게임 시세·공지, 암호화폐, 환율, 서비스 상태를 투명하게 보여주는 개인용 대시보드다.

증거: 최신 공개 대시보드 전체 화면.

## 페이지 4 — 기획: 기술 스택

Next.js App Router, React, TypeScript strict, Tailwind CSS, TanStack Query, Vitest, Testing Library, Playwright, Vercel을 사용한다.

## 페이지 5 — 기획: 위젯 5개

로스트아크 공지, 로스트아크 거래장 시세, Upbit 암호화폐 시세, 한국수출입은행 고시 환율, GitHub 서비스 상태를 제공한다.

증거: 상태별 카드 검증 화면.

## 페이지 6 — 기획: 시스템 구조

브라우저는 `/api/widgets/*`만 호출한다. 서버 provider adapter가 외부 API를 조회하고 공통 `WidgetData<T>`로 정규화한다. 공통 계층은 timeout, retry, 429, 503, TTL cache, promise dedupe, stale fallback을 담당한다.

## 페이지 7 — 기획: 구현 API

| Route | 공급자 | TTL |
|---|---|---:|
| upbit-ticker | Upbit | 20초 |
| status | GitHub Status | 5분 |
| exchange-rate | 수출입은행 oapi | 1시간 |
| lostark-notices | Lost Ark notices | 15분 |
| lostark-market | Lost Ark markets | 5분 |

## 페이지 8 — 과제 요구사항: 전체 판정

C01~C18, C20, C23~C28은 로컬/공개 검증 완료다. C19·C21·C22는 recover-d2 asset과 실제 다음 KST 날짜 앱 재실행이 필요해 보류다.

## 페이지 9 — C01~C10: 공개 데이터와 맥락

무로그인 공개 주소, Upbit 공개 BTC/KRW 일봉, 값, KRW, 출처 URL, 원천 시각, 조회 시각, Asia/Seoul가 확인된다.

증거: 현재값·단위·출처·조회 시각 화면.

## 페이지 10 — C01~C10 증거

`Codex_T04_독립감사.../C1_현재값_단위_출처_조회시각.png`

## 페이지 11 — C11: 비밀 없는 호출

소스·배포 파일·네트워크·Git의 비밀값 검색 결과는 0건이며 브라우저는 provider를 직접 호출하지 않는다.

증거: 독립감사 메타 화면과 비밀값 검사 로그.

## 페이지 12 — C06: 출처 한 번 클릭

화면의 Upbit 출처 링크를 한 번 클릭하면 원자료 페이지가 열린다.

증거: 출처 링크 클릭 원자료 화면.

## 페이지 13 — C12~C16: 장애 5종 표

timeout은 지연/Abort, 401/403은 인증 실패, 429는 호출 제한, offline은 연결 실패, schema 변경은 필수 필드 없는 JSON으로 재현한다. 모두 합성 시험값만 사용한다.

## 페이지 14 — C12: timeout 증거

느린 외부 응답을 시간 초과 상태로 구분한다.

## 페이지 15 — C13: 인증 실패 증거

외부 원천 401/403 거절을 인증 실패로 표시한다.

## 페이지 16 — C14: 호출 제한 증거

HTTP 429를 호출 제한으로 표시한다.

## 페이지 17 — C15: 오프라인 증거

연결 실패를 오프라인 상태로 표시한다.

## 페이지 18 — C16: 형식 변경 증거

필수 필드가 없는 JSON을 정상 데이터로 사용하지 않는다.

## 페이지 19 — C17~C18: 마지막 정상값과 오래된 데이터

실패 뒤 마지막 정상값을 지우지 않으며 오래된 데이터 표시를 붙인다. 정상값이 없으면 숫자를 만들지 않고 빈 상태를 보여준다.

## 페이지 20 — C19: 다시 시도와 복구

다시 시도 후 fresh 상태와 정상 데이터로 돌아온다. 공개 recover-d2 asset과 실제 다음 날짜 저장은 보류다.

## 페이지 21 — C20~C24: KST 일별 기록

같은 KST 날짜는 고유 행 1건으로 병합한다. 2026-08-25와 2026-08-26 공개 원천의 원천·저장·계산 입력·화면값을 대조했다.

## 페이지 22 — 실제 두 날짜 증거

2026-08-25는 109,165,000 KRW, 2026-08-26은 109,830,000 KRW다.

## 페이지 23 — 변화값 손계산

`109,830,000 - 109,165,000 = +665,000 KRW`. 변화율은 `0.6091…%`이며 화면의 `+0.61%`와 일치한다.

## 페이지 24 — 원천·저장 불일치 방어

원자료와 저장값이 다르면 비교를 중단하고 경고를 표시한다.

## 페이지 25 — C25~C28과 AI 3줄

개인정보·비밀값 0건, 합성 장애와 실제 기록 분리, 4개 제목의 검증 안내, AI/직접 판단/불채택 사유를 완료했다.

- AI에게 맡긴 일: 기존 코드 보존, 장애 5종, 일별 기록, 비교, 테스트, 증거 문서
- 직접 판단한 일: 복사본 작업과 실제 Upbit 일봉 사용
- 따르지 않은 일: 증거 덮어쓰기와 미완료 배포의 허위 통과

## 페이지 26 — 검증 안내서: 어디로 가나요

공개 대시보드와 같은 주소의 `/verification`으로 이동한다. 원본 프로젝트 배포본과 T04 복사본 공개 주소를 혼동하지 않는다.

## 페이지 27 — 검증 안내서: 3단계 행동

1. 값·단위·출처·조회 시각·실제 날짜 2건과 출처 링크를 확인한다.
2. 이전/현재 값과 방향·차이·단위를 확인하고 동기화를 반복해 중복을 확인한다.
3. 장애 5종, 오래된 데이터, 빈 상태, 다시 시도 복구를 확인한다.

## 페이지 28 — 검증 안내서: 통과와 안 될 때

통과는 값의 맥락, KST 두 날짜, 비교값, 서로 다른 장애 문구, stale/empty가 보이는 것이다. 값이 다르면 `trade_price`와 `candle_date_time_kst`, 날짜가 중복되면 localStorage 고유키, 장애가 같으면 장애 유형과 다시 시도를 확인한다.

## 페이지 29 — 트러블슈팅: 빌드와 브라우저

PowerShell npm.ps1 차단은 `npm.cmd`로 해결했다. prerender의 document 접근은 서버 경계 검사를 추가했다. 상대시각 hydration 불일치는 고정 server snapshot과 client clock 구독으로 해결했다. 예상된 503만 콘솔 검사에서 구분했다.

## 페이지 30 — 트러블슈팅: 공급자와 배포

수출입은행 도메인을 신규 oapi로 이전하고 오류 코드와 빈 응답을 분리했다. Lost Ark의 잘못된 CategoryCode와 없는 기본 아이템을 수정했다. Vercel 전환 중 일시 404는 숨기지 않고 실패·성공 증거를 모두 남겼다.

## 페이지 31 — 트러블슈팅: 증거 덮어쓰기

최초 재검증의 파일명 충돌 이후 실행 UTC 시각을 폴더명으로 고정했다. 기존 폴더가 있으면 중단하며 최초 덮어쓴 픽셀은 복구 불가라는 사실도 기록했다.

## 페이지 32 — 작업내역: 구현 과정

전략 분석→계획→표준 문서→공통 계약→5개 provider→캐시·오류 처리→로컬 검증→Vercel 배포→T04 복사본과 카드 3~5 보완 순으로 진행했다.

## 페이지 33 — 작업내역: 주요 결정

서버 Route Handler, 위젯 5개, 서버 혼잡도 제외, 공통 오류 계약, 실행별 증거 보존을 주요 결정으로 기록했다. 원본 보존을 위해 T04 복사본에서만 변경했다.

## 페이지 34 — 작업내역: 최종 검증

lint, typecheck, 단위 테스트, production build, Playwright E2E를 통과했다. T04 확장 최종 결과는 Vitest 41개와 Playwright 9개 통과다.

## 페이지 35 — 최종 상태

공개 주소, 실제 데이터 맥락, 비밀 없는 호출, 장애 5종, stale/empty/retry, KST 중복 방지, 실제 원천 대조, 손계산, 검증 문서와 증거를 완료했다. 실제 다음 KST 날짜 앱 재실행과 제공되지 않은 asset SHA-256은 보류다.
