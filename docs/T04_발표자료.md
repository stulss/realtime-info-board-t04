# T04 발표자료 — 오늘의 진짜 정보판

## 1. 한 문장 소개

Upbit BTC/KRW 일봉을 매일 기록하고, 값이 늦거나 실패해도 마지막 정상값과 현재 상태를 숨기지 않는 공개 정보판입니다.

## 2. 공개 화면

- 결과물: <https://realtime-info-board-t04.vercel.app/>
- 장애 검증: <https://realtime-info-board-t04.vercel.app/verification>
- 소스: <https://github.com/stulss/realtime-info-board-t04>

로그인·설치 없이 공개 주소를 열 수 있습니다. 메인 화면에서 값, 단위(KRW), 출처, 원천 관측 시각, 조회 시각, Asia/Seoul 기준, 일별 기록과 비교값을 확인합니다.

## 3. 시연 순서(약 2분)

1. 메인 화면에서 BTC/KRW 값과 `KRW`, Upbit 출처 링크, 두 시각, `Asia/Seoul`을 보여줍니다.
2. 일별 기록 표에서 2026-08-25와 2026-08-26을 확인하고 `+665,000 KRW`, `+0.61%` 변화가 두 값의 손계산과 같은지 설명합니다.
3. 출처 링크를 한 번 눌러 원자료 페이지가 열리는 것을 보여줍니다.
4. `/verification`에서 timeout, 인증 실패, 호출 제한, 오프라인, 응답 형식 변경을 차례로 재생하고, 정상값 보존·오래된 데이터·빈 상태·다시 시도를 보여줍니다.

## 4. 핵심 설계

- 외부 API는 Next.js Route Handler에서 호출해 브라우저에 비밀값을 노출하지 않습니다.
- 원천 응답의 필수 필드를 검증하고, 실패 종류별 `error kind`를 구분합니다.
- 마지막 정상값은 오류 시 덮어쓰지 않고 `오래된 데이터`로 표시합니다.
- 일별 키는 `날짜 + 데이터 종류`이며 Asia/Seoul 기준으로 같은 날짜 중복을 막습니다.
- 원천값·저장값·계산 입력값·화면값을 표로 나란히 대조합니다.

## 5. 검증 결과

- lint, typecheck, Vitest 41개, production build, Playwright E2E 9개 통과
- 합성 장애 5종 각각의 스크린샷과 SHA-256 보관
- 비밀값·개인정보 로컬 검색 0건
- 실제 공개 원천 기록 2건: 2026-08-25 / 2026-08-26

상세 판정은 [C01–C28 매핑](00_과제_요구사항_매핑.md), [검증 체크리스트](T04_검증_체크리스트.md)를 참고합니다.

## 6. 스크린샷 증거

최신 전체 증거: [`docs/검증스크린샷/2026-08-27T05-19-10-578Z/`](검증스크린샷/2026-08-27T05-19-10-578Z/)

실행마다 UTC timestamp 폴더를 새로 만들고, 기존 폴더나 파일이 있으면 중단하도록 설정했습니다. 따라서 증거 파일은 덮어쓰지 않습니다.

## 7. 남은 확인

실제 다음 KST 날짜에 공개 앱을 다시 실행해 두 번째 날짜 저장을 직접 확인하는 절차와, 제공되지 않은 `t04-real-information-board` asset 패키지 SHA-256 대조는 아직 `[~]`입니다. 합성 fixture나 기존 원천 이틀 기록을 이 절차의 대체 증거로 주장하지 않습니다.

## 8. AI와 본인 판단

- AI에게 맡긴 일: 오류 상태 분기, 일별 중복 방지, 대조표와 E2E 증거 구조를 구현했습니다.
- 직접 판단한 일: 공개 비개인 원천으로 Upbit을 선택하고 실제 원천값·단위·기준 시각을 대조했습니다.
- AI 제안을 따르지 않은 일: 실제 두 날짜가 없는 상태에서 합성 데이터를 실제 기록처럼 저장하지 않았습니다.
