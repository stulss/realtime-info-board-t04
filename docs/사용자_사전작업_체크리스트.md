# 사용자 사전작업 체크리스트

> 목적: 다음 AI 작업자에게 프로젝트를 넘기기 전에 **사용자 본인만 할 수 있는 계정·승인·비밀값 작업**을 분리한다.
> 확인일: 2026-08-26 (Asia/Seoul)
> 원칙: 이 문서에는 실제 JWT, 서비스키, 비밀번호를 절대 적지 않는다.

## 0. 먼저 알아둘 현재 상태

- 코드 구현과 로컬 자동 검증은 완료되었다.
- Upbit와 GitHub Status는 키 없이 실제 값이 표시된다.
- Lost Ark와 한국수출입은행 위젯은 사용자 계정으로 발급받은 서버용 키가 필요하다.
- 비공개 GitHub 저장소 `https://github.com/stulss/realtime-info-board` 연결과 첫 push를 완료했다. Vercel 배포는 아직 하지 않았다.
- 한국수출입은행 API는 신규 `oapi.koreaexim.go.kr` 도메인과 `RESULT 2/3/4` 오류 처리를 반영하고 자동 검증했다.
- 사용자는 발급받은 두 키를 GitHub나 AI 채팅에 올리지 않고, Vercel 프로젝트를 만든 뒤 Environment Variables에 직접 입력한다.

## 2. Lost Ark JWT 준비

1. Lost Ark OpenAPI에서 `MY CLIENTS` → `CREATE A NEW CLIENT`로 이동한다.
2. Client Name, 실제 사용할 서비스 URL, 설명을 입력하고 약관·개인정보처리방침을 확인한 뒤 client를 만든다.
   - 아직 공개 URL이 없다면 임의의 가짜 URL을 쓰지 않는다. 포털이 로컬 URL을 허용하는 경우에만 `http://localhost:3000`을 사용하고, 허용하지 않으면 아래 항목을 `공개 URL 필요`로 남겨 다음 Codex가 Preview URL을 먼저 만들게 한다.
3. 발급된 JWT를 비밀번호 관리자 등 안전한 곳에 저장한다.

- [x] Lost Ark client 생성 완료 / 공개 URL이 필요해 다음 Codex에게 선행 배포 요청
- [x] JWT를 안전한 곳에 별도 보관
- [x] JWT를 문서·채팅·GitHub Issue·스크린샷에 붙이지 않았음

공식 문서는 생성된 JWT를 신뢰할 수 있는 서버 측 애플리케이션에 보관하도록 안내한다. 인증 형식은 서버 코드가 처리하므로 `.env.local`에는 JWT 값만 입력해도 된다.

## 3. 한국수출입은행 서비스키 준비

1. 공공데이터포털의 [한국수출입은행 환율 정보](https://www.data.go.kr/data/3068846/openapi.do) 페이지에 로그인한다.
2. `활용신청`에서 개인 서비스키 또는 프로젝트 서비스키 중 본인 운영 방식에 맞는 키를 신청한다.
3. 승인 상태와 발급 키를 공공데이터포털 마이페이지에서 확인하고 안전하게 보관한다.

- [x] 환율 OpenAPI 활용신청 완료
- [x] 서비스키 발급·승인 상태 확인
- [x] 서비스키를 안전한 곳에 별도 보관
- [x] 서비스키를 문서·채팅·URL·스크린샷에 붙이지 않았음

공식 페이지 기준으로 비용은 무료이며 개발·운영 단계 모두 자동승인으로 안내되지만, 실제 화면의 최신 이용조건이 다르면 그 화면을 우선하고 다음 작업자에게 차이를 알린다.

## 4. 로컬 비밀값 설정 (선택)

프로젝트 루트 `C:\Users\stuls\Desktop\Agent\realtime-info-board`에서 `.env.example`을 복사해 `.env.local`을 만든 뒤 아래 **변수 이름만 유지하고 실제 값은 본인 컴퓨터에서 직접 입력**한다.

```dotenv
LOSTARK_API_KEY=<발급받은 JWT>
EXIM_SERVICE_KEY=<발급받은 서비스키>
LOSTARK_MARKET_ITEM_NAME=명예의 파편 주머니(대)
EXIM_CURRENCY=USD
```

- [ ] 로컬 실데이터 검증이 필요할 때만 `.env.local` 파일 생성
- [ ] 로컬 검증 시 `LOSTARK_API_KEY` 입력
- [ ] 로컬 검증 시 `EXIM_SERVICE_KEY` 입력
- [ ] 어떤 변수에도 `NEXT_PUBLIC_` 접두사를 사용하지 않음
- [ ] `.env.local`을 메신저·AI 채팅·메일에 첨부하지 않음

값을 화면에 출력하지 않고 입력 여부만 확인하려면 PowerShell에서 아래 명령을 실행한다.

```powershell
$requiredNames = @('LOSTARK_API_KEY', 'EXIM_SERVICE_KEY')
foreach ($name in $requiredNames) {
  $hasValue = Select-String -LiteralPath '.env.local' -Pattern "^$([regex]::Escape($name))=.+$" -Quiet
  if ($hasValue) { "[OK] $name" } else { "[확인 필요] $name" }
}
```

`Get-Content .env.local`처럼 비밀값 전체를 터미널에 출력하는 명령은 사용하지 않는다.

## 5. GitHub·Vercel 관련 사용자 결정

GitHub 연결은 완료되었다.

- [x] Git 초기화·첫 커밋·GitHub push 승인
- [x] 비공개 저장소 생성: `https://github.com/stulss/realtime-info-board`
- [ ] Vercel에서 위 GitHub 저장소를 Import

Vercel 프로젝트가 만들어지면 Dashboard → Project → Settings → Environment Variables에서 다음 이름을 등록한다.

- `LOSTARK_API_KEY` — Production 필수, Preview에서 검증할 경우 Preview에도 추가
- `EXIM_SERVICE_KEY` — Production 필수, Preview에서 검증할 경우 Preview에도 추가
- `LOSTARK_MARKET_ITEM_NAME` — 선택
- `EXIM_CURRENCY` — 선택, 기본값 `USD`

- [ ] Vercel 팀/개인 계정 중 배포 위치 결정
- [ ] Vercel 환경변수에 `NEXT_PUBLIC_`를 사용하지 않음
- [ ] 비밀 변수는 가능하면 Sensitive로 저장
- [ ] 환경변수 추가·변경 후 반드시 새 배포 또는 Redeploy가 필요함을 확인

## 7. 다음 작업자 호출 조건

필수 완료 기준은 다음 세 가지다.

1. Vercel에서 `stulss/realtime-info-board` 저장소를 Import한다.
2. Vercel Environment Variables에 두 키를 직접 설정한다.
3. 배포 주소를 다음 검증 작업자에게 전달한다.

셋 중 하나라도 불명확하면 다음 작업자에게 실제 키를 보내지 말고, 어떤 단계에서 막혔는지만 전달한다.
