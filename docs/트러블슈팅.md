# 트러블슈팅

## 2026-08-26 — PowerShell에서 npm.ps1 실행 차단
- **문제:** `npm --version`이 ExecutionPolicy 오류로 실패했다.
- **시도/비교:** 정책을 변경하면 사용자 시스템 전역에 영향을 주므로 변경하지 않았다.
- **해결:** Windows 실행 파일인 `npm.cmd`를 사용했다.
- **배운 점:** 로컬 정책을 우회하기보다 동일 도구의 승인된 실행 진입점을 사용한다.

## 2026-08-26 — Next.js prerender의 document 접근
- **문제:** 첫 production build에서 TanStack Query의 `refetchInterval` 함수가 서버에서 `document`를 읽어 실패했다.
- **해결:** `typeof document !== "undefined"` 경계를 추가해 서버 안전성을 확보했다.
- **결과:** production build 통과.

## 2026-08-26 — 상대시각 hydration 불일치
- **문제:** Playwright는 통과했지만 SSR과 브라우저의 `Date.now()` 차이로 hydration 경고가 발생했다.
- **해결:** `useSyncExternalStore`의 서버 snapshot을 고정하고 클라이언트 clock 구독 후 상대시각을 갱신했다. 로딩 fallback의 동적 `fetchedAt`도 제거했다.
- **결과:** 후속 E2E에서 hydration 경고가 사라졌다.

## 2026-08-26 — 키 미설정 503과 콘솔 검사
- **문제:** production E2E에서 키 기반 API 3개가 의도한 HTTP 503을 반환했고 Chrome이 이를 콘솔 오류로 기록해 1개 검사가 실패했다.
- **해결:** 예상된 503 리소스 메시지만 제외하고 hydration·JavaScript 런타임 오류는 계속 실패하도록 검사를 정교화했다.
- **결과:** production E2E 5/5 통과.

## 2026-08-26 — 스크린샷 증거 덮어쓰기
- **문제:** 최초 재검증이 같은 파일명을 사용해 22:03~22:04 최초 이미지의 내용을 22:06 결과로 덮어썼다.
- **사용자 피드백:** 보고서 증거자료이므로 모든 실행본을 남겨야 한다.
- **해결:** 실행 UTC 시각을 폴더명으로 사용하고 Playwright 부모 프로세스에서 ID를 고정했다. 이후 기존 이미지 수정·삭제 없이 실행별로 새 폴더를 만든다.
- **남은 사실:** 덮어쓴 최초 픽셀 버전은 복구할 수 없으며, 현재 루트 4장은 22:06 결과다. 이 사실을 `검증스크린샷/README.md`에 기록했다.

## 2026-08-26 — 한국수출입은행 기존 도메인 종료
- **문제:** 구현 당시 사용한 `www.koreaexim.go.kr` API 도메인의 병행 가동이 2026-04-30 종료됐다.
- **해결:** 요청 주소를 `oapi.koreaexim.go.kr`로 변경하고 `RESULT 2` 요청 오류, `3` 인증키 오류·파기, `4` 일일 1,000회 제한을 구분했다.
- **빈 응답:** 비영업일 또는 영업일 11시 이전 `null`/빈 배열은 장애로 단정하지 않고 최근 7일 고시를 역순 탐색한다.
- **호출 정책:** 당일 11시 전후 갱신을 반영하면서 제한을 지키도록 서버 TTL을 1시간(최대 24회/일)으로 정했다.
- **결과:** adapter 테스트 5건을 추가하고 전체 단위 테스트 17건과 production E2E 5건을 통과했다.

## 2026-08-26 — 최초 Vercel 실데이터 3/5 성공
- **문제:** 최초 배포에서 Lost Ark 거래장이 공급자 HTTP 400, 환율이 최근 7일 USD 고시 404를 반환했다. 공지·Upbit·GitHub는 정상이었고 공개 응답에 비밀 키 패턴은 없었다.
- **원인:** 거래장 POST가 유효하지 않은 `CategoryCode: 0`을 사용했다. 환율은 고정 환경변수와 공급자 통화코드 원문의 공백에 영향을 받을 여지가 있었다.
- **해결:** 거래장은 `/markets/options`의 유효 상위 카테고리를 순회하고, 환율은 검증된 화면 선택값과 trim한 공급자 코드를 비교한다. 고정 아이템·통화 환경변수는 화면 검색·목록으로 대체했다.
- **검증:** adapter 테스트 2건을 추가했고 전체 19건, build, 로컬 E2E 5/5를 통과했다. 원격 재배포 검증은 후속 로그에 누적한다.

## 2026-08-26 — Vercel 의존성 경고 검토
- **ESLint:** v9.39.5는 EOL 경고가 맞다. v10.9.1을 시험 설치했지만 `eslint-config-next@16.3.3` 내 플러그인 3개가 아직 v10 peer 범위를 지원하지 않아 강제 업그레이드를 철회했다. 빌드를 막지 않는 경고로 남기고 공식 호환 후 갱신한다.
- **install script:** `unrs-resolver@1.12.2`의 postinstall이 `napi-postinstall`로 네이티브 패키지를 준비하는 코드임을 검토했다. npm 공식 `allowScripts` 형식으로 정확한 버전만 승인했다.

## 2026-08-26 — 검색 UI E2E locator 중복
- **문제:** `아이템 검색`이 form과 input 양쪽 접근성 이름에 매칭되어 첫 E2E가 4/5로 실패했다.
- **해결:** textbox 역할과 이름을 함께 지정해 실제 입력 요소만 선택했다.
- **증거:** 실패 세트 `2026-08-26T14-33-18-304Z`와 성공 세트 `2026-08-26T14-33-48-437Z`를 모두 보존했다.

## 2026-08-26 — 원격 첫 화면의 거래장 기본 검색어 404
- **문제:** 원격 API 계약에서 `파괴강석` 검색을 포함한 5개 공급자는 모두 정상이었지만, 첫 화면 기본값 `명예의 파편 주머니(대)`가 현재 거래장에 없어 콘솔 404로 E2E가 4/5였다.
- **해결:** 실제 배포 API에서 조회 성공을 확인한 `파괴강석`을 초기 검색어로 변경했다. 사용자는 검색창에서 다른 아이템으로 자유롭게 변경할 수 있다.
- **증거:** 실패 원격 실행 세트를 삭제하지 않고 증거 색인에 누적한다.
