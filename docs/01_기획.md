# 01 기획 (설계 문서)

> 최종 갱신: 2026-11-04. 과제(T04) 당시의 5개 위젯 구성은 `docs/T04_과제_README.md`와 `계획.md`에 기록으로 남아 있고, 이 문서는 **현재 제품(Daylog)** 기준이다.

## 프로젝트 개요
한국에서 일상에 쓰는 정보(내 위치 날씨·대기질, 비트코인, 환율, 공휴일)를 한 화면에서 보여 주고, **하루 한 번 날짜별로 자동 기록**해 변화를 보여 주는 개인용 정보판.

## 기술 스택
- Next.js 16 (App Router) + React 19 + TypeScript strict, Tailwind CSS 4
- TanStack Query 5, Pretendard(SIL OFL), Lucide(ISC)
- Vitest + Testing Library(단위 108), Playwright(E2E), axe-core(접근성)
- Vercel 배포: <https://realtime-info-board-t04.vercel.app/>

## 위젯 구성 (현재 8개)
날씨(내 위치)·예보·대기질(Open-Meteo), 비트코인(Upbit), 원화 환율(한국수출입은행, 키 없으면 Frankfurter 참조환율), 공휴일(Nager.Date), 기상청 실황·에어코리아(`DATA_GO_KR_SERVICE_KEY`가 있을 때만 표시). 한국 일상에 쓰지 않는 해외·게임 위젯은 제거했다.

## 시스템 구조
브라우저는 `/api/*` Route Handler만 호출 → 서버가 외부 API를 조회(키는 서버 환경변수에만) → 공통 `WidgetData<T>` 형식으로 정규화. 공통 계층이 timeout·재시도·TTL 캐시·동일 요청 dedupe·마지막 성공값(stale) 전환을 담당한다. 브라우저는 `/api/config`로 키 보유 여부(true/false)만 받아, 키가 필요한 위젯은 없으면 요청하지 않고 안내를 보여 준다.

## 구현된 API
| Route Handler | 공급자 | 비고 |
|---|---|---|
| `/api/widgets/weather`, `weather-forecast`, `air-quality` | Open-Meteo | 위치 기반(소수 2자리 반올림) |
| `/api/widgets/upbit-ticker`, `upbit-daily-history` | Upbit | 시세·일봉(과거 채움) |
| `/api/widgets/exchange-rate` | 한국수출입은행 / Frankfurter | 키 없으면 대체 |
| `/api/widgets/holiday` | Nager.Date | |
| `/api/widgets/kma-weather`, `airkorea` | 공공데이터포털 | 키 필요 |
| `/api/history` | Open-Meteo·Frankfurter | 8월 1일부터의 일별 과거값 |
| `/api/place`, `/api/config` | BigDataCloud / 서버 설정 | 위치 이름·키 보유 여부 |
| `/api/verification/failure` | (시뮬레이션) | 장애 대응 데모용, 외부 호출 없음 |

## 화면
- `/` 하늘 히어로 → 브리핑 → 위젯 타일 → 날짜별 기록(개요·달력·추세)
- `/about` 데이터 출처·개인정보·키 연결 방법
- `/verification` 장애 대응 데모(장애 5종 재현·복구)
